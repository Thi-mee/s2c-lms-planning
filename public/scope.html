Variable LMS · Product dossier · Reviewed 18 September 2026

Build the essential path first.

The walking skeleton exercises the architectural boundaries before the full MVP is expanded.

Derived documentation

This summary is not an implementation specification. Canonical repository sources govern: Scope · Build sequence · Decision gates. The identity foundation is implemented; learning features remain planned. See the current implementation and local setup.

Included

A complete cohort-learning product.

People and licensing

Organization bootstrap, explicit role grants, invitation/activation, deactivation, learner capacity and revocable authentication.

Authoring and delivery

Single-owner courses, ordered modules and text lessons, required readings, published-course cohorts and assigned learning runs.

Assessment and evidence

Practice/graded quizzes, immutable answers, audited allowance resets, run completion and fixed-template course certificates.

Discussion and operations

Cohort forums, durable emails, transactional audit, versioned deployment, explicit migrations and tested backup/restore guidance.

Deferred

Scope stays deliberate.

No public catalog/self-enrollment, generic uploads/video hosting, SCORM/xAPI, billing engine, collaborator editing, notification center, arbitrary certificate templates or public verification in MVP. No mandatory Redis, broker, Kubernetes or microservices infrastructure.

Helm launch support depends on customer requirements. Shared-tenant SaaS and service extraction require separate justified decisions. Transfer is not implemented unless explicitly required and specified.

Sequence

Deliver usable slices.

  1. Organization/Admin bootstrap and authenticated shell.
  2. Create and publish one course.
  3. Schedule and staff a cohort.
  4. Invite and activate a Learner within licensed capacity.
  5. Assign a new run and record required-content completion.
  6. Submit a graded assessment; evaluate completion and issue/download the course credential.
  7. Expand remaining MVP and qualify a versioned release with recovery tests.

Gates

Foundations are ready; some feature choices remain.

Open local decisions cover license expiry/downsize, cohort boundary access, reading-completion signal, attempt lifecycle, multi-select scoring, feedback/preview, live edits and administrative reissue. Release gates include privacy/retention, measurable operating targets, supported platforms, formal accessibility acceptance and distribution terms.

These gates have owners in the canonical question register; this dossier does not choose defaults for them. There are no promised release dates or later-feature phase commitments.
