# Product Principles

> **Status:** Draft  
> **Last Updated:** June 2026

---

## Purpose

Product principles are guidelines that help make consistent decisions about what to build and how to build it. When in doubt, refer to these principles.

---

## Principles

> **Draft:** These are starting principles. They should be discussed and refined.

### 1. Documentation first, implementation second

Define what we are building before writing code. Understanding the problem is more important than shipping quickly.

### 2. Start simple, add complexity later

Build the simplest version that is useful. Add features based on validated needs, not speculation.

### 3. Learner experience is the priority

When trade-offs arise, prioritize the learner's experience. The platform exists to help people learn.

### 4. Clarity over cleverness

Prefer clear, predictable behavior over clever shortcuts. This applies to both the user experience and the codebase.

### 5. Decisions should be reversible

Avoid locking into choices that are expensive to change. Prefer flexible designs where possible.

### 6. Track what matters

Build progress tracking and analytics into features from the start, not as afterthoughts.

### 7. Iterate openly

Document decisions, assumptions, and open questions transparently. The planning process should be as clear as the final product.
